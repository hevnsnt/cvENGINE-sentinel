# Changelog

## Unreleased

### Fixed
- **nuclei: a host that is down is unreachable and stays due, not recorded as scanned clean.** Seen in a lab with the pinned nuclei 3.11.1: a dead address came back with no findings and nothing unreachable, three ways. nuclei words a request to an address nothing answers on as `port closed or filtered`, which the error-log reader did not know; with the targeted and deep tags every host also logs `interactsh client not initialized` and `no port provided in network protocol request` (template problems, not answers), which made a dead host look reached; and a closed port that only some template asks for (AJP, 8009) must not make a live web server unreachable. A host is now judged by the ports it is asked on (its own, or 80 and 443 for a bare host).
- **nmap: an address it scanned and found nothing open on is covered.** The fingerprint pass runs with `--open`, so nmap writes a host only when it has an open port (a lab run over five addresses listed four while its own count said five), and the server read the missing row as "this Sentinel did not cover it" and asked again at every pass. When nmap's own count says it scanned every address it was given, the unlisted ones get a row with no ports.
- **WPScan: the redirect hops share one time limit.** Each of up to four scans got the whole limit, so a chain of slow scans could run for four times what the server waits and the watchdog allows, and the result was lost.
- **The watchdog does not stop probe batches before their own limit.** `http_probe` and `route_probe` (batch limit 20 minutes) and `supplier_check` (25 minutes) were stopped at the 20 minute default with an error, instead of finishing and reporting what they read.
- **bbot: a run that refuses a missing module is an error.** bbot prints `Could not find scan module` and exits 0 with nothing found; it was reported as a clean discovery. A missing preset was already an error.
- **A tool stopped at its time limit says so.** The error was the start of its command line (clipped before the words "timed out"); it now names the tool and the limit.
- **Tools and base image at their newest releases.** Go 1.27.4 (builds nuclei and naabu), testssl.sh 3.2.5 (now fetched from its GitHub release tag; the 3.2.4 file there is byte-identical to the one testssl.sh served), Playwright 1.65.1 with its Chromium 158.0.8127.18 (its seccomp profile is unchanged, so the vendored copy stays), bbot 3.1.0, the Ubuntu 26.04 base image's current digest (sha256:065aa862...), nuclei-templates v10.5.2, and aardwolf 0.2.17, PyMySQL 1.2.4 and dnspython 2.9.2. Kingfisher stays at 2.16.0 until the server's reviewed validation allow-list is moved with it.
- **bbot 3.1.0, held to the pace of 3.0.2.** The release changed several defaults that send more than 3.0.2 did, and this Sentinel's network was once blocked by a CDN for scanning too hard, so the command now sets them back (after the task's own values; nothing in a task can change them): DNS `dns.threads` 25 (subdomain presets) or 10 and `dns.max_concurrency` the same, instead of 50 and 256; DNS brute force capped at 1000 queries a second with 3 retries a name (3.1.0: no cap, 20 retries); the new baddns `DELEGATION` check off (it adds `_acme-challenge`, `_dmarc` and 15 DKIM lookups a host); `lightfuzz` told to skip hosts behind a WAF (`avoid_wafs: always`, 3.1.0 fuzzes them and pads request bodies to get past the WAF) and `nowafpls` excluded (neither is in the presets a task may name: checked with bbot 3.1.0's own module list, so this is a guard); `js_unpacker` (new, requests every source map a script names) excluded; `dnsdumpster` and `otilabs` (they now need an API key and only soft-failed) excluded unless the project stored a key for them. A technology bbot 3.1.0 names by product and also gives a CPE for is stored as that CPE, as bbot 3.0.2 sent it, so the server still reads its version. bbot's `blastdns`, `blasthttp`, `baddns` and `badsecrets` are now pinned in the Dockerfile and checked by the release gate. The nuclei service-port allowlist is regenerated for v10.5.2: 307 templates (ssl/deprecated-tls gained a raw SSLv2 frame to port 443 and is left out until it is read; 31 listed templates changed only their EPSS score and signature, and their review entries moved to the new hashes). **bbot 3.1.0 has not been run against live targets**: it was checked against its own release, its module list and its dry-run command parsing only.
- **nuclei: a tag filter no template matches is nothing to check, not a failure.** The server asks for tags such as `haproxy` at severity `info`; when no template in the set matches, nuclei exits 1 (`no templates provided for scan`) and the task failed. 29 tasks in two days on the VPS, the same tag sets every time, and those hosts stayed due for ever. With a filter the result is now no findings and `no_templates`; without one, an empty template set is still an error (the templates are missing).
- **nuclei: a run that runs out of time keeps what it found.** Before, the whole run was lost; now its findings are returned and every target is named unreachable, so none is recorded as scanned clean.
- **nuclei: each run ends before the server stops waiting for it.** The daemon passed no time limit, so every nuclei run could take 3600 s while the server waits 900 s (light), 1800 s (targeted) or 3600 s (deep) plus a little per target, and late results were thrown away (13 in two days). Limits now come from `cvengine_scanner.flags.TASK_LIMITS`, 60 s under the server's wait; the longest production runs fit.
- **A tool's failure message says its error, not nuclei's JSON-library warning.** The message keeps 200 characters of stderr and nuclei opens every run with a line about `sonic/ast`, so each failure read `...fallback to encoding/json[FTL] Could not run nuclei: no templ`. That line is left out of the message; the whole stderr stays on the exception.
- **WPScan without an API token is not asked for vulnerable plugins and themes.** WPScan refuses `vp`/`vt` without a token and aborts the whole scan, so sites of projects with no token were never scanned (14 of the last 90 runs). It now lists the plugins and themes it detects (`p`, `t`) and their versions, which the server's CVE feed reads.
- **WPScan follows a redirect on the same site once.** WPScan stops at a redirect rather than follow it, so a site that answers on its `www.` twin or another path was never scanned (32 of the last 90 runs). A redirect to the same host or its `www.` twin is scanned (scope-checked again like any URL); one that leaves the site is not followed.
- **WPScan follows up to three redirects on the same site.** http to https and then the apex to `www.` is two hops, and the scan stopped at the second, so the server read a failed scan. Each hop is judged by scope and the site check again, never goes to another site and never back to a URL already scanned.
- **testssl.sh gets `-6` for an IPv6 address, and a Sentinel with no IPv6 route says so.** testssl.sh stops with "Only IPv6 address(es) available" without it, so no IPv6 address was ever audited. A Sentinel with no route to an IPv6 address now reports `this Sentinel cannot reach IPv6 addresses` for a TLS audit and leaves it out of a naabu run (listed as unfinished) instead of waiting out naabu's time limit; found by running the real tools on a private IPv6 docker network.
- **secrets_scan: one name that does not resolve no longer fails its whole batch.** A resolver error is an `OSError`, not a scope refusal, so it escaped the per-host loop and ended the task: 22 batches of up to 25 hosts in two days. That host is skipped and the rest of the batch is read.
- **OpenVAS: the `openvas-scanner` image pin points at an image that exists.** Greenbone replaced the image behind `stable` and removed the pinned digest on 11/10, so `docker compose up` with the OpenVAS profile failed to pull it (`scripts/greenbone-digests.sh`: MISSING). Both pins move to the current `stable` digest.
- **nuclei sends a port only the templates of the protocol that speaks there, one at a time, paced.** A task's `name:22`, `name:25` or `name:143` used to get the whole template set (over 11,000 http templates, plus the raw tcp, javascript and ssl ones): the scanned host's sshd logged 34,000 "banner exchange: invalid format" lines in 20 minutes and refused its own administrator's logins. The task now carries an optional `services` map (what speaks on each `host:port`: `web`, `unknown`, or a protocol class such as `ssh`, `smtp`, `imap`, `tls`) and a `budget`. The web targets run first, together, without the raw tcp and javascript templates and with a per-host rate (25 requests a second a host, `-per-host-rate-limit`). Each non-web `host:port` runs by itself, one template at a time as its own nuclei process, with a pause of at least 500 ms between runs (5.5 s on ssh, so OpenSSH 9.8+ never penalises the Sentinel), for at most 300 seconds, with only the templates of its protocol; a port whose service has no class of its own, or that nothing is known about, gets the generic network templates (tcp, javascript and ssl types that belong to no class) and never an http template. nuclei's own `-rl` paces only http and dns requests, so the pause is the pace. A non-web port runs only templates on a pinned allowlist (default deny): the Sentinel library ships `cvengine_scanner/data/nuclei_service_allowlist.json`, the id and sha256 of every nuclei-templates v10.5.2 template a service run may send (307 of the 523 tcp, javascript and ssl templates: ssh 26, ftp 108, telnet 3, smtp 9, imap 2, pop3 2, mysql 4, mssql 1, redis 4, memcached 1, smb 11, rdp 1, vnc 1, tls 38, generic network 133; 6 critical, 15 high), and a template that is not listed, or whose file differs from the recorded sha256 (checked when the listing is read and again just before it is sent), is not run on a service port. `scripts/generate_service_allowlist.py` makes the list: a template is kept only if it carries no excluded tag, has no block of another protocol, is not self-contained, sends no UDP, calls only read-only javascript library calls, passes the earlier content rule (no payloads, no login or authentication step, at most 10 requests), passes an independent decode of every string (plain, hex and base64: no user name, password, token, cookie, community string, authorization header or authentication message), and, when it is of the exploit class (tag cve, rce, kev... or severity medium and up), was read by a person and found to change nothing on the target (`nuclei_service_review.json`). `nuclei_service_left_out.json` records every template left out and why (216), among them the seven the third review found that still sent a credential (`backdoored-zte`, `tidb-unauth`, `clickhouse-unauth`, `CVE-2022-24706`, `CVE-2026-83548`, `CVE-2026-55040`, `CVE-2024-54772`), `pgsql-detect` and `dionaea-ftp-honeypot-detect`; two templates the old name rule refused without cause (`smb-signing`, `perforce-detection`: read, and measured on nuclei 3.11.1 to send an SMB2 negotiate and a `p4 info`, no login) are restored. A template that names a port of its own runs only on a target on that port. `scripts/check_tool_versions.py --fail-if-behind` fails the release gate when the pinned nuclei-templates release is not the one the list was generated for. An unknown port whose banner probe is read is charged to that port's time budget, and a host name is resolved once, for the scope judgment, and the probe connects to the address that was judged. Measured on nuclei 3.11.1 with sshd on 2222 and a counting listener on 22 of the same host: the ssh javascript templates (`Port: "22"` in their arguments) connect to the target's own port, 2222, and none opened a connection to 22. A port that is only partly checked (out of time part way, some runs failed, the template listing failed) is also reported as unreachable so the server keeps it due. An unknown port that answers with an SSH banner on connect (one short connection, nothing sent; not through an egress proxy) is treated as ssh. Measured in a lab (nuclei 3.11.1, throwaway listeners on a private network): the old behaviour opened 6,226 connections to one port in 57 s, 103 at once, up to 334 in a second, and made a real OpenSSH 10.3 drop connections; now the ssh class makes 44 connections in 147 s (2 at once, at most 4 in a second) and OpenSSH logs no penalty, and no class opened more than 5 at once. A template run that fails, or a class with no template, never fails the task or loses findings: the result's `not_checked` names each port not fully checked and why, a task checks at most 6 non-web ports (the server sends the rest in another task) and the web pass runs first and keeps 65 percent of the task's time. A task can make the budget gentler, never harsher (`cvengine_scanner.flags.NUCLEI_SERVICE_BUDGET`). A target the server did not label is read by its port number, and a port in no table is never web. Contract: optional `services` and `budget` on the nuclei targets, optional `not_checked` on the nuclei results, no version change.
- **nuclei now runs on the server's approved template set.** The task names its bundle inside `template_policy`, and the Sentinel looked for it at the top level, so under the default read-only policy every nuclei task failed, and under the all-templates policy the Sentinel ran the templates baked into its image, never refreshed. A read-only task whose bundle is not packed yet is given back to be retried, not failed. The result names the template release the run used (`templates_release`).
- **A host nuclei never reached is not reported as scanned.** nuclei exits cleanly with no output for a host nothing answered. The run now reads nuclei's error log and names those hosts in `unreachable` (the template test reports them as errors).
- **nuclei findings keep their evidence.** The raw request and response are kept (clipped, credentials redacted) instead of dropped with `-omit-raw`, with the CVE ids, CVSS score, references and remediation text the template carries.
- **testssl reports whether a handshake happened and its exit code.** A port that completes no TLS handshake sends no "not vulnerable" answers, because nothing was tested.
- **nmap reports a host it gave up on as `timed_out`,** and an address it did not report gets no clean row.
- **naabu full-port discovery can finish.** One time-limit function serves nmap and naabu, a run that runs out of time reports the addresses it did not reach (`incomplete`, `unfinished`) instead of an error, and the fingerprint pass scans the ports of its task with the extended port set and the reviewed scripts.
- **A DNS timeout on a mail name is unknown, not "no mail".** The MX or CNAME lookup that failed is named in `unknown_names`.
- **OpenVAS: a host gvmd finished without any answer is reported in `unreached_hosts` and not as scanned,** so a host that was only offline closes none of its earlier findings.
- **bbot wildcard names are not subdomains.** A name tagged `wildcard` and the `_wildcard.<zone>` placeholder are dropped.
- **`detect_tools` declares a tool only when its version probe exits cleanly,** and **a discovery sweep that died is an error,** not "no host is up".

### Added
- A Sentinel that is not the built-in scanner now reports `info.features: ["bbot_keys"]` in its heartbeat: it reads a bbot discovery task's API keys through the
  single-use secret read (`POST sentinel/tasks/<id>/secret`), keeps them only in a 0600 file inside a fresh 0700 directory for the run, and masks them. A cvENGINE
  server sends the project's discovery API keys only to a Sentinel that says so (and that its owner has not opted out); an older Sentinel never says it and never gets
  them. Optional field, no contract change, no new task kind, task payload unchanged. Every key is now also masked in each batch posted and in the final result and
  any error text (not only in bbot's error stream), and a key directory a crashed run left in the temp directory is removed at the next start.
- A Sentinel watchdog (`client/watchdog.py`, docs/WATCHDOG.md): a thread apart from the task threads, ticking every 10 seconds, on by default
  (`CVENGINE_SENTINEL_WATCHDOG=0` switches it off). W1 stops a task's whole process group at a per-kind hard deadline (the tool's own budget plus a grace; the
  owner can raise it, never lower it) and reports `error` "timed out after N minutes"; W2 stops a group that used no CPU and moved no bytes for N minutes (a
  hung tool); a stopped nuclei run that had printed findings reports them as `done`, one with none is an `error`. W3 breaks the memory-budget deadlock: waiters that
  waited 3 minutes behind long runs may start inside an overcommit of at most 25 percent of the budget and only within the real free memory measured from /proc and
  the cgroup (a floor of the larger of 300 MB and 15 percent of the limit); nothing is killed for it. W4 kills tool process groups that outlived their task and reaps
  their zombies. W5 replaces a stuck heartbeat thread and ends the process (exit code 3) for a poll loop stuck for 5 minutes, for every Sentinel; the image health
  check also fails on a stale watchdog, heartbeat or poll loop. W6 stops taking work under 300 MB of free disk and removes only its own temp and cache files.
  W7 the heartbeat's optional `info.watchdog` (last tick, actions, kills, overcommit, reasons). W8 per-rule variables, one log line per action, and a kind
  stopped 3 times in an hour is not asked for for 30 minutes. No contract change, no new task kind.
- **AI-written checks run on your own Sentinels (contract version 4).** With no built-in scanner, cvENGINE now sends its AI-written and approved
  nuclei checks (`nuclei_validate`) and its scan path survey (`path_probe`) to the project's own Sentinels. A Sentinel that is not the built-in scanner
  runs a check only when all of these hold: the task names the sha256 of the template (`template_sha256`), the file it wrote and read back hashes to it,
  its server names the same hash and mode for that task when asked separately (`GET sentinel/tasks/<id>/check`), the template passes the server's
  read-only rules (`cvengine_scanner.checks`, one shared test corpus) and it reaches only the task's own target and port (no literal port, no `port`
  key). A result line for a host the task did not name is never a hit, and the result echoes the hash it ran. The image gains PyYAML 6.0.3.
  Second security pass: the whole template is held to an allowlist (`cvengine_scanner.check_allowlist`): one YAML document that PyYAML and
  nuclei's yaml.v3 read alike (no duplicate keys, second document, anchors, merge keys, tags, YAML 1.1 words, U+2028), known keys only, and every
  `{{...}}` expression, `dsl` string and variable may call only side-effect-free string, encoding, hash and compare helpers (no `resolve`, `jarm`,
  `public_ip`, `wait_for`, `print_debug`, clock or random helpers); a raw request is exactly one GET, HEAD or OPTIONS request with no body or `@`
  annotation, and no request sets `Host` (outside raw), `Authorization`, `Cookie`, a forwarding header or a credential-looking value. The server's
  check answer names the task's sorted targets too, compared with the task's (hashes with `hmac.compare_digest`). nuclei is pointed with `-r` at a
  resolver of the Sentinel's own that answers each target name only with the addresses scope judged and nothing else (a name whose answer changes after
  it was judged still reaches only the judged address; an install proxy resolves the name itself, outside this resolver, and a name with non-ASCII
  letters is pinned in its Unicode form while nuclei asks in punycode, so it gets no answer), and
  runs with a minimal environment (no Sentinel secret), a 2 GiB data limit, its time limit and a 16 MiB cap on the output read. The hash protects
  against a check changed in transit, edited after dispatch or changed on disk before the run; not against a compromised server, against which the
  Sentinel's own allowlist and target limit are the defence.
  Third security pass: a string literal in an expression may not contain a quote character of either kind (nuclei before 3.9.0 ended a string at either
  kind, which hid a `resolve()` call from the allowlist), and a Sentinel refuses to run an AI-written check on a nuclei older than 3.9.0 or with no
  readable version; the gate refuses with a reason instead of raising on a deeply nested document or a value of an unexpected type (nesting is capped at
  20); names are matched whole (no trailing newline); control characters and U+00A7 are refused in decoded strings too; a plain decimal such as
  `cvss-score: 9.8`, CRLF line ends, upper-case metadata keys and a list of authors are accepted (both YAML readers read them the same way).
- Kingfisher 2.18.1 (was 2.16.0): the Dockerfile pin and both checksums (from the release's own files, build attestation verified), the library constant and the README row.
- **The image's tools are checked against their newest releases.** `scripts/check_tool_versions.py` reads every pin (the Dockerfile versions and base image digest, `requirements.txt`, the pip bootstrap pins, the Greenbone image digests) and prints each one beside the newest upstream release. A weekly run keeps one issue open while something is behind, every pull request gets a warning, and *Tag a release* refuses to tag while a tool is behind or a lookup fails (`--fail-if-behind`).
- A durable result spool (`client/spool.py`): a result cvENGINE does not take (an update, a restart, an outage) is written to disk (0600, atomic) and delivered oldest
  first, with a capped backoff, for up to 6 hours (`CVENGINE_SENTINEL_SPOOL_HOURS`, `0` = off; size limit `CVENGINE_SENTINEL_SPOOL_MAX_MB`) instead of being released after
  5 tries in 2 minutes. It is delivered before the first heartbeat after a reconnect or a start, a held result's task still counts as running in the heartbeat, and the
  heartbeat reports `info.spool` (`count`, `oldest_seconds`, optional) for the Sentinels page. An entry past the window is kept under `spool/expired/`. No contract change.
- A Sentinel that cvENGINE asks to update (heartbeat answer `update.requested` with `update.target`) can drain and exit with code 76 so its supervisor brings the
  newest image: `CVENGINE_SENTINEL_UPDATE_EXIT=1`, `client/selfupdate.py`, `scripts/pull-on-exit.sh`. It never leaves while a task runs past the drain limit, never to the build it
  already runs, never twice for the same target within 6 hours, and never for the built-in scanner or a machine whose own self-update ceiling is off.

### Changed
- The heartbeat and the poll log an outage once, then at most every 10 minutes, instead of one line per attempt. The quick result retries are 4 tries within 20 seconds (were 5 within 120).
- README: "cvENGINE asks for the newest version" describes who acts on the request (the host updater, the exit-code supervisor, the server's host for the built-in scanner).
